From a test session to an issue draft in five steps

BugSnap records the supported interactions you perform and turns them into a report you can review and edit.

  1. Start recording

    Open the popup on the page you are testing.

  2. Use the site

    Click, type, and change form fields as you normally would.

  3. Stop recording

    BugSnap saves the session to its backend.

  4. Review the steps

    Open the report and check each reproduction step.

  5. Copy Markdown

    Paste it into GitHub Issues, Jira, Taiga, or similar.

BugSnap does not find bugs for you, does not guarantee complete or accurate steps, and does not replace a human tester. Treat every report as a draft to review.

What the beta does today

Browser interaction recording

A content script listens for clicks, text input, and field changes on the page you are testing. Password, hidden, and one-time-code fields are recorded without their values.

Structured reproduction steps

Events become a readable, numbered list instead of raw HTML.

Markdown export

One button on the report page copies the report as Markdown.

Shareable reports

Each saved session gets a report link served by the BugSnap backend.

A simple manual-testing workflow

Start, test, stop, review. No test scripts to write.

Developer-friendly reporting

Output is plain Markdown that pastes into the tools your team already uses. Features may have limitations during beta.

Install the beta in Chrome

This takes about five minutes and needs no command line. You will load the extension from a folder on your computer.

  1. Download the ZIP

    Current version: v0.1.0-beta.1. File: bugsnap-beta.zip

    Download BugSnap Beta

    Only download releases from the official project repository. Installation is manual, so Chrome will not verify the file for you.

  2. Extract the ZIP

    Windows

    Right-click the ZIP, choose Extract All…, pick a folder such as Desktop, then Extract.

    macOS

    Double-click the ZIP in Finder. A folder with the same name appears next to it.

    Do not select the ZIP file itself in Chrome. Chrome needs the extracted folder. Keep the folder somewhere permanent: if you move or delete it, the extension stops working.

  3. Open Chrome Extensions

    Click Chrome's address bar, type this address, and press Enter. Pasting works too.

    chrome://extensions

    Web pages cannot open chrome:// links, so copy and paste it yourself.

  4. Turn on Developer mode

    On the Extensions page, find the Developer mode switch in the top-right corner and turn it on. New buttons appear, including Load unpacked.

  5. Click Load unpacked

    Click Load unpacked and choose the extracted folder that contains manifest.json directly inside it.

    BugSnap should now appear in your extensions list.

  6. Pin it and run a test

    • Click the puzzle-piece icon in Chrome's toolbar and click the pin next to BugSnap.
    • Open the site you want to test and click the BugSnap icon.
    • Click Start Recording, do a few clicks and form inputs, then click Stop Recording.
    • Click Open report, review the steps, and use Copy Markdown.

Troubleshooting

BugSnap has known beta reliability issues. These steps help in many cases, but none is a guaranteed fix.

The “Load unpacked” button is missing

Turn on Developer mode at the top right of chrome://extensions. If the switch is locked or missing, your browser may be managed by a school or employer, and you will need to ask your administrator.

Chrome reports a manifest error

You most likely selected the wrong folder or the ZIP itself. Select the extracted folder that directly contains manifest.json. If the file is missing, download the ZIP again from the official release.

Recording does not start

Chrome blocks extensions on pages such as chrome:// and the Chrome Web Store, so test on a normal website. If the popup says it cannot access the page, reload the tab and try again. This can be a known beta issue, and a reload is a workaround rather than a fix.

The extension says no events were recorded

Nothing supported was captured. Make sure recording was started on the tab you are using, perform at least one click or text entry, then stop. If it keeps happening, please report it with your browser version and the site you tested.

The first actions are missing

This is a known beta issue: early actions can be lost, especially on the first load of a page. Wait a moment after starting before you act, and check the report to add anything that is missing.

The report cannot be loaded

Check your internet connection and wait a little before retrying, since the backend may respond slowly. Make sure you opened the full link from the popup. If it still fails, open an issue with the time of the attempt. Do not post the session ID publicly unless you are comfortable with others viewing that report.

Read this before testing

BugSnap is an early testing build. Help it improve by reporting what breaks.

Beta notice

  • Some recordings may fail or miss the first actions.
  • Review generated reports before sharing them.
  • Avoid recording passwords, one-time codes, payment details, or other sensitive information.
  • Recorded data is sent to the configured backend to create the report link. Anyone who has a report link can open that report.
  • Do not use BugSnap with confidential or production data. See the privacy notice.

Frequently asked questions

Is BugSnap available on the Chrome Web Store?

No. It is a beta build distributed as a ZIP and installed manually.

Why do I need Developer mode?

Chrome only lets you load extensions from a local folder when Developer mode is on. The Chrome Web Store is the other route, and BugSnap is not published there yet.

Does BugSnap require Node.js on my computer?

No. Node.js is only used to run the backend server, which is already deployed. You just need Chrome and the extension folder.

Where does BugSnap send reports?

When you stop recording, the extension sends the recorded events to the BugSnap backend at https://bugsnap-9nc9.onrender.com, which stores the session and serves the report page. The backend code has no login or access control, so anyone with a report link can view it. Treat links as shareable.

What should I do if recording fails?

Work through the troubleshooting panels, then open an issue with the steps you followed, your browser, and any console errors.

How do I report a bug?

Open an issue on the GitHub issue tracker. Remove passwords, tokens, and personal data first.

Can I uninstall BugSnap?

Yes. Go to chrome://extensions, find BugSnap, and click Remove. Reports already saved on the backend are not deleted by removing the extension.
